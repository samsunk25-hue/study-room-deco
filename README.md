# 🏠 스터디룸 — 학습 정리하고 내 방 꾸미기

중학생이 **오늘 배운 내용을 형성평가 + 한 줄 요약으로 정리**하면 AI 조교가 판정하고,
통과하면 **코인과 가구 상자**를 받아 **단원별 2.5D 아이소메트릭 방**을 꾸미는 게임화 학습 플랫폼입니다.
(기획서 PRD/GDD v4.0·v5.0 기반)

## 두 가지 실행 모드

| | 로컬 모드 (시연) | 서버 모드 (실제 운영) |
|---|---|---|
| 설정 | `CONFIG.gasUrl` 비움 | `CONFIG.gasUrl` 에 GAS 웹앱 URL |
| 로그인 | 학번 + 이름 | **학번 + 비밀번호** (기기를 바꿔도 같은 방) |
| 저장 위치 | 이 브라우저(localStorage) | **교사가 지정한 구글 드라이브 폴더**에만 |
| 코인·보상·판정 | 브라우저 | **서버**(조작 불가) |
| 정답·핵심 개념 | js/units.js | **단원 시트** (학생 기기로 전송되지 않음) |
| 교사 인증 | PIN | **구글 계정 + 관리자 승인** |
| 친구 방·스티커 | 사용 불가 | 사용 가능 |

로컬 모드는 `index.html` 을 열면 바로 됩니다. 서버 모드는 아래 설치를 따라 주세요.

## 핵심 루프

1. **학습하기** → 단원 선택 → 형성평가 채점 → 한 줄 요약 작성 → AI 조교 판정(규칙 기반, 외부 AI 전송 없음)
   - 길이 부족 / 무의미어 / 교과서 복사 / 오개념 패턴 / 핵심 개념 누락 / 인과 연결 없음 → **정답 대신 발판 힌트**
   - 실패 시 **그 단원 방에 오개념 먼지 괴물** 등장 → 재도전 통과 시 정화 + 보너스
2. **보상**: 코인(기본 + 퀴즈 정답 + 첫 시도 보너스) + 가구 상자 (일반/레어/에픽, 이벤트 기간 한정판). 단원마다 하루 1회
3. **내 방**: **단원마다 방이 따로** 있고, 그 단원에서 얻은 가구만 그 방에 들어갑니다. 드래그 배치, R 키 회전, 색상 리폼(9색), 스타일 4종, 벽지·바닥, 히든 시너지 3종
4. **서재**: 요약 기록, 우수 요약, 월 1회 AI 개념도 액자, 받은 영감 스티커
5. **친구 방**(서버 모드): 같은 반 친구 목록 → 🟢 바로 방문 / 🟡 노크 → 허락 시 30분 입장 / 🔴 방문 불가.
   방문자는 **방 모습과 통과한 요약(학습자료)만** 볼 수 있고 점수·시도 횟수·먼지 괴물·승인 전 사진은 보이지 않습니다. 영감 스티커를 남기면 소액 코인(하루 3회)
6. **상점**: 커스텀 사진 액자(업로드 전 **개인정보·초상권·저작권 동의 체크** 필수, 교사 승인 전 흑백), O2O 교실 쿠폰
7. **보호**: 심야 22~07시 잠금(서버 시간 기준), 수업 시간 인테리어 잠금(설정), 제출 연타 방지, 비밀번호 10회 오류 시 10분 잠금

## 서버 모드 설치 (교사·관리자)

1. 교사가 지정한 드라이브 폴더 안에 스프레드시트 **스터디룸 DB** 를 만듭니다. (이 폴더가 학생 데이터의 유일한 저장소)
2. 시트에서 **확장 프로그램 → Apps Script** 를 열고 파일을 추가합니다.
   - `Code.gs` ← `gas/Code.gs`
   - `catalog.gs` ← `js/catalog.js` / `judge.gs` ← `js/judge.js` / `engine.gs` ← `js/engine.js` (내용 그대로)
   - `units.gs` ← `js/units.js` (선택, 예시 단원 채우기용)
3. 시트를 새로고침 → 메뉴 **🏠 스터디룸 → ① 초기 설치** (시트 소유자 = 관리자). 시트·하위 폴더·10분 동기화 트리거가 만들어집니다.
4. **② 예시 단원 채우기**를 누르면 `js/units.js`(units.gs)에 들어 있는 **중학교 과학 1~3학년 전 단원 23개**(2022 개정 교육과정 성취기준, 비상교육 대단원 기준)가 `단원` 시트에 들어갑니다. 같은 단원ID는 덮어쓰므로 여러 번 눌러도 중복되지 않습니다. 메뉴 대신 `gas/단원_시트_가져오기.csv`를 **파일 → 가져오기 → 현재 시트에 추가**로 넣어도 됩니다.
5. **배포 → 새 배포 → 웹 앱** (실행 계정: 나 / 액세스: 모든 사용자) → URL 을 `js/catalog.js` 의 `CONFIG.gasUrl` 에 넣습니다.
6. 학생용 앱은 GitHub Pages 또는 Firebase Hosting에 올립니다(아래 참고). `js/units.js`는 `.gitignore`/`firebase.json`이 자동으로 제외하므로 정답이 학생 기기로 가지 않습니다. 파일이 없어도 앱은 정상 동작합니다.
7. 다른 교사를 추가하려면 **⑥ 교사 등록 승인(관리자)** 에 이메일을 입력합니다. 폴더가 공유되고 `교사` 시트에 등록됩니다.

### 교사 메뉴
| 메뉴 | 기능 |
|---|---|
| ③ 평가기록부 지금 갱신 | 행=학번, 열=날짜 기록부를 즉시 재생성 (평소엔 10분마다 자동) |
| ④ 승인 처리 적용 | `승인요청` 시트에서 체크한 사진·쿠폰을 학생 상태에 반영 (학생 접속 시에도 자동 반영) |
| ⑤ 학생 비밀번호 초기화 | 임시 비밀번호 0000, 다음 로그인 때 학생이 새로 설정 |
| ⑦ 심야 잠금 켜기/끄기 | 테스트용 |
| ⑧ 내 교사 접속 코드 보기 | 교사가 학생용 앱에 **시간 제한 없이** 접속하는 코드(30일 유효). 로그인 화면 "교사로 접속"에 입력. 모든 학생 방·학습자료 열람 가능 |
| ⑨ 가입 코드 설정 | 공개 호스팅에서 아무나 가입하지 못하도록 학생 가입 때 입력할 코드를 정함 |

## 학생용 앱 호스팅 (GitHub Pages / Firebase Hosting)

학생용 앱은 정적 파일(`index.html`, `css/`, `js/`)뿐입니다. **호스팅 서비스에는 학생 데이터가 전혀 가지 않습니다.**
- 앱은 `CONFIG.gasUrl`(Apps Script)로만 통신합니다. `index.html`의 콘텐츠 보안 정책(CSP)이 그 외 주소로의 네트워크 요청을 브라우저 단에서 차단하고, referrer 차단으로 서버 주소가 밖으로 새지 않게 합니다.
- Firebase SDK, 애널리틱스, Firestore 등을 추가하지 마세요. 호스팅 서비스가 남기는 것은 일반 웹 접속 기록(IP, 시각)뿐입니다.
- `.gitignore`와 `firebase.json`이 정답 파일 `js/units.js`, 기획서, 서버 코드를 업로드에서 제외합니다. 정답은 서버의 `단원` 시트에만 있습니다.
- 공개 주소에서는 누구나 가입 화면을 볼 수 있으므로 **⑨ 가입 코드**를 설정하고 수업 시간에 학생에게 알려 주세요.

**GitHub Pages**
1. GitHub에 저장소를 만들고 이 폴더를 push 합니다. (`.gitignore` 덕분에 units.js·docx는 올라가지 않습니다)
2. 저장소 **Settings → Pages → Branch: main / (root)** 저장.
3. 1~2분 뒤 `https://<계정>.github.io/<저장소>/` 가 학생용 주소입니다.
4. 코드를 고치면 다시 push 하면 됩니다. 서버(Apps Script) 재배포는 Code.gs 등 서버 파일을 고쳤을 때만 필요합니다.

**Firebase Hosting**
```
npm install -g firebase-tools
firebase login
firebase init hosting        # 기존 firebase.json 유지, public: . 선택
firebase deploy --only hosting
```
Hosting 외의 Firebase 기능은 켜지 않습니다. `firebase.json`에 보안 헤더(CSP, no-referrer, nosniff, frame 차단)가 들어 있습니다.

**교사 접속**: 로그인 화면 아래 "👩‍🏫 교사로 접속"에서 ⑧ 메뉴로 받은 코드를 입력하면 심야·수업 시간 잠금 없이 사용할 수 있고, 친구 방 탭에서 모든 학생의 방과 통과 요약을 볼 수 있습니다. 교사 계정의 방·코인은 시험용이며 평가기록부에 포함되지 않습니다.

### 폴더 구조 (교사 지정 폴더 안)
```
스터디룸 DB (스프레드시트)
  ├ 학생계정   학번 | 이름 | 비밀번호해시 | 솔트 | 파일ID | 가입일 | 최근접속 | 공개설정 | 초기화   (학번 오름차순)
  ├ 단원       단원ID | 과목 | 단원명 | 성취기준 | 교과서 발췌 | 핵심 개념 | 오개념 | 문항 | 사용
  ├ 평가기록부 행=학번, 열=날짜 (자동 생성, NEIS 세특 참고용)
  ├ 승인요청   사진·쿠폰 승인 체크박스
  ├ 소셜       노크/허락/스티커 로그 (7일 후 자동 정리)
  └ 교사       승인된 교사 이메일
학생데이터/    <학번>.json — 방·가구·코인·요약 기록 (학생별 1파일)
승인대기사진/  교사 확인용 사진 (승인 후 자동 삭제)
```

## 개인정보·보안 설계 요약

- 학생 식별 정보와 학습 내용은 **교사 폴더 밖으로 나가지 않습니다.** 외부 AI(Gemini 등) 호출이 없고, 판정은 서버의 규칙 엔진이 수행합니다.
- 비밀번호는 솔트 + SHA-256 해시로 저장되며, 로그인 토큰은 서명 검증(HMAC)으로 확인합니다.
- 코인·가구·판정은 서버가 결정하므로 브라우저 조작으로 바꿀 수 없습니다. 클라이언트는 명령만 보냅니다.
- 친구에게 보이는 정보는 `Engine.publicView` 가 만드는 **방 모습 + 통과 요약**뿐입니다.
- 사진은 액자에만 쓰이고 학생 기록 파일 안에만 저장됩니다. 교사 확인용 사본은 승인 후 삭제됩니다.
- 앱이 업데이트되어도 `Engine.migrate` 가 이전 버전 데이터를 변환해 가구·기록을 보존합니다.
- 학부모(법정대리인) 동의서에 "학교 지정 구글 드라이브 폴더 저장"을 명시하는 것을 권장합니다.

## 동시 접속 대응

- 제출은 전역 잠금 없이 **학생별 파일**에만 기록합니다. 평가기록부 집계는 트리거가 따로 수행합니다.
- 서버가 혼잡하거나 네트워크가 끊기면 클라이언트가 명령을 **큐에 보관하고 지수 백오프로 재시도**하며, 화면 상단에 "저장 대기 n건"을 표시합니다.
- 보상이 걸린 제출은 서버 응답을 기다리며, 실패 시 작성한 요약을 유지한 채 다시 제출할 수 있습니다.

```
index.html        화면 골격

js/engine.js      게임 로직: 상태 마이그레이션, 명령 적용, 보상, 공개 뷰 (공용)
js/api.js         서버 통신 + 재시도 큐
js/room.js        아이소메트릭 방 렌더링·드래그 앤 드롭·시너지 (내 방 / 친구 방 인스턴스)
js/app.js         화면 전환·로그인·학습 루프·단원별 방·친구 방·상점·서재·교사
gas/Code.gs       Apps Script 서버 (계정, 상태 파일, 단원 시트, 승인, 소셜, 교사 메뉴)
```
